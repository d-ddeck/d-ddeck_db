기준: `master`의 `6f1aa17` (v1.0.12)
작업 위치: `/home/leemoon/ddeck-worktrees/service-work-types`

## 변경 내용

대응 기록에 **업무 구분**을 추가했습니다. 기존 장비·증상 분류인 ‘서비스구분’과 별도로 선택합니다.

| 기본 코드 | 표시 이름 |
| --- | --- |
| AS | 수리/점검 |
| CS | 고객 대응 |
| PO | 구매 |

- 새 접수는 사용 가능한 AS를 기본 선택합니다. 선택을 해제하면 미분류로 저장할 수 있습니다.
- 업무 구분과 관계없이 기존 접수 필수 항목과 완료 처리 규칙은 유지합니다.
- 기존 건은 미분류로 보존합니다. 기존 수정 화면을 열어도 AS로 자동 변경하지 않습니다.
- 등록·수정·상세·모바일 목록·데스크톱 목록에 구분을 표시합니다.
- 목록에서 업무 구분 또는 미분류 조건으로 조회할 수 있습니다. 구분 코드·이름으로 검색도 가능합니다.
- 통계에 업무 구분 필터와 집계 축을 추가했습니다. 요약·추이·교차표·목록 내려받기에 같은 필터가 적용됩니다.
- 대응 기록 Excel 끝에 ‘업무 구분 코드’와 ‘업무 구분’ 열을 추가했습니다. 기존 열의 위치는 유지합니다.
- 전체 통계 Excel에는 ‘업무 구분’ 시트를 추가했습니다.

**신규 접수번호는 선택한 업무 구분 코드로 발급합니다.** 예: `AS-202609-0001`, `CS-202609-0001`, `PO-202609-0001`. 관리자가 추가한 업무 구분 코드도 적용하며, 코드별·월별로 순번을 발급합니다. 업무 구분을 선택하지 않으면 기존 `ticket_prefix` 설정(기본 AS)을 사용합니다. 기존 접수도 업무 구분을 변경해 저장하면 변경 시점의 월을 기준으로 새 번호를 발급합니다. 같은 업무 구분을 유지하거나 다른 항목만 수정하면 번호는 유지합니다. 업무 구분을 해제하면 기본 접두어로 재발급합니다. 이전 번호는 재사용하지 않고 변경 전·후 번호를 작업 기록과 감사 이력에 남깁니다. 긴 사용자 정의 코드를 지원하려면 서버 업데이트 시 `alembic upgrade head`로 접수번호 열을 80자로 확장하는 `e628b429ad51` 및 발급 번호 보존용 `f739c530be62` 마이그레이션을 적용해야 합니다. 견적서 기능은 [견적서 검토 문서](QUOTATIONS_REVIEW.md)에서 확인할 수 있습니다.

## 구분 항목 추가 방법

1. 관리자 이상 계정으로 **관리 → 기능 설정 → 서비스(AS) 설정**을 엽니다.
2. **업무 구분**에서 항목을 추가합니다.
3. 코드와 이름을 입력합니다. 예: `INSTALL` / `설치 지원`.
4. 접수 화면을 다시 열면 추가한 항목을 선택할 수 있습니다.

이름·색상·순서 변경, 사용 중지, 삭제는 기존 코드 관리 화면에서 처리합니다. 코드는 생성 후 바꾸지 않으며 다른 코드는 새 항목으로 추가합니다. 사용 중지·삭제 항목은 새로 지정할 수 없지만, 기존 건에는 남고 그 건을 수정할 때도 유지할 수 있습니다. 같은 코드를 다시 추가하면 기존 코드 관리 규칙에 따라 복원됩니다. 이름 변경은 과거 건에도 반영됩니다.

## 병합 후 적용 사항

서버와 앱을 함께 반영해야 합니다. 새 앱의 업무 구분 API는 이전 서버에 없습니다.

업무 구분 마이그레이션 `ecdd8d8aea3c → b9a381e076cf`는 대응 테이블에 nullable `work_type_id`, 외래 키와 인덱스를 추가합니다. 기본 AS/CS/PO 항목은 서버 시작 시 생성합니다. 기존 데이터의 업무 구분은 NULL입니다.

운영 반영은 병합 결정 이후에 진행합니다. 반영 시 DB 백업과 서비스 중지 후 해당 환경에서 `alembic upgrade head`를 적용하고 새 서버를 시작해야 합니다. 다운그레이드하면 업무 구분 연결 컬럼이 없어지므로, 입력한 구분 연결을 보존하려면 백업이 필요합니다.

현재 작업은 별도 브랜치와 작업 폴더에만 있으며 **master 병합, 릴리스, 운영 DB 변경은 수행하지 않았습니다.** 원래 작업 폴더의 미커밋 파일도 그대로 보존했습니다.

추가 견적서 마이그레이션은 `b9a381e076cf → c43194e8a260`입니다. 통합 검증 결과와 검증 서버 반영 상태는 견적서 검토 문서를 참고하세요.
