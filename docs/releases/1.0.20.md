# d-ddeck 1.0.20 — 로그인 정보 노출 개선 및 사설 CA 기반 HTTPS 준비

작성일: 2026-09-29 · 릴리즈 준비: 2026-10-01  
상태: 사전 릴리즈 · 자동 업데이트 제외

v1.0.19 이후 구현·검증한 내용과 운영 환경 전환 준비 사항을 정리했습니다. **서버 HTTPS 전환 전에는 기존 HTTP 사용자에게 배포하지 마세요.** 사전 릴리즈이므로 기존 정식 버전의 자동 업데이트 대상으로 제공하지 않습니다.

Windows·Android 설치 파일에는 회사 CA 공개 인증서와 HTTPS 기본 연결 설정을 포함합니다. 기존 설치의 주소 설정이 남아 있다면 관리자 연결 설정에서 변경하거나 새로 발급된 서명 설정 파일을 가져오세요.

## 로그인 및 연결 설정

- 로그인 화면에서 업무 서버 주소와 포트 표시를 제거하고 ‘디떽 업무 서버’로 표시합니다.
- 서버 연결 확인 결과에는 연결 상태만 표시하며 주소를 함께 출력하지 않습니다.
- VPN 상태 표시에서 엔드포인트 주소를 제거하고 연결 상태 중심으로 표시합니다.
- 로그인 화면의 서버 주소 직접 입력란을 제거했습니다. 주소 직접 변경은 관리자용 ‘이 기기 연결 설정’ 화면으로 이동했습니다.
- 최초 설치 또는 연결 장애 시 로그인 전에도 관리자 서명이 있는 JSON 연결 설정 파일을 가져올 수 있습니다.
- 연결 파일의 서명·용도·유효기간을 검증하고 변조되거나 만료된 파일은 거부합니다. 가져오기 유효기간은 최대 7일입니다.
- 연결 대상 변경 전에 기존 서버 세션을 종료해 기존 인증정보가 새 서버로 전달되지 않도록 처리했습니다.
- 연결 설정 파일에는 비밀번호·토큰·개인키를 포함하지 않습니다. 서명은 파일의 진위를 검증하며 주소 자체를 암호화하지는 않습니다.

## HTTPS 통신 보호

- 원격 API 요청은 HTTPS를 사용하도록 제한했습니다. 서버 PC의 숫자 루프백 주소는 HTTP 예외로 유지합니다.
- API 요청의 자동 리디렉션을 차단하고 인증서 검증을 유지합니다.
- Android 네트워크 보안 설정에서도 평문 HTTP 통신을 차단합니다.
- 도메인 없는 환경을 위해 회사 사설 CA와 IP SAN 서버 인증서 발급 도구를 추가했습니다.
- 회사 CA 공개 인증서를 앱에 포함하고, API 통신과 업데이트 다운로드에서 신뢰하도록 연결했습니다.
- 앱 내부의 CA 신뢰 설정을 사용하므로 Windows·Android의 기기 전체 신뢰 저장소를 변경할 필요가 없습니다.
- 인증서 체인·유효기간·서버 IP 검증을 유지하며 인증서 오류를 무시하는 방식은 사용하지 않습니다.
- CA 개인키와 서버 개인키는 저장소 밖에 분리 보관하고, 앱에는 공개 인증서만 포함합니다.

## 서버망 이전 및 배포 준비

- 추가 공유기 아래 별도 서버망으로 이전하는 구성을 검토하고 새 서버 IP 적용을 확인했습니다.
- 새 사내망과 WireGuard 대역에 맞춰 서버 인증서를 재발급하고 서명된 HTTPS 연결 파일을 갱신했습니다.
- nginx 설치·실행 상태를 확인했습니다.
- nginx의 TLS 1.2/1.3, 사내망·VPN 대역 허용 및 기타 접근 거부 설정을 준비했습니다.
- 인증서 유효기간·IP 일치·개인키 권한 검사와 전체 인터넷 대역 허용 방지 검사를 추가했습니다.
- 기존 수동 실행 서버를 systemd 서비스로 전환하는 적용 스크립트를 준비했습니다. Google 안전 백업과 사전 검사를 거친 뒤 backend를 루프백 주소에만 바인딩하도록 구성합니다.
- 전환 스크립트는 기존 서비스·TLS 설정을 덮어쓰지 않고 중단하며, 전환 실패 시 기존 설정 정리와 수동 서버 재실행을 시도하도록 작성했습니다. 실제 관리자 권한 적용·실패 복구 경로의 운영 검증은 남아 있습니다.

실제 서버 주소, 허용 대역 및 명령어는 [사설 CA 배포 문서](../private-ca-deployment.md)를 참고하세요.

## 검증 결과

- Flutter 전체 테스트 271개 통과, 19개 건너뜀.
- 정상 회사 CA 인증서는 연결되고 미신뢰 CA 및 IP 불일치 인증서는 거부되는 실제 TLS 연결 테스트 통과.
- 원격 HTTP 요청이 인증정보 전송 전에 차단되는 검사 통과.
- 연결 설정 파일의 서명·변조·만료·용도 검증 통과.
- 사설 CA·서버 인증서 제약조건, 개인키 파일 권한 및 인증서 덮어쓰기 방지 검사 통과.
- 새 서버 IP에 대한 인증서 체인·IP 일치 검증 통과.
- Dart 분석, Python Ruff 검사 및 Linux 디버그 빌드 통과.
- HTTPS 전환 스크립트 구문 검사와 설정 미리보기 확인 완료.

## 운영 적용 대기 사항

- 운영 서버의 실제 HTTPS 전환과 사내망·VPN 접근 제한은 아직 적용하지 않았습니다. Ubuntu 관리자 인증을 통한 적용이 필요합니다.
- 새 앱은 원격 HTTP 접속을 차단하므로 기존 HTTP 서버에 바로 배포하면 접속할 수 없습니다. 서버 전환과 새 앱 배포를 같은 유지보수 일정에 맞춰 진행해야 합니다.
- Windows·Android 설치 파일은 GitHub 릴리즈 빌드로 제공합니다. 실제 기기의 로그인·다운로드·VPN 접속 검증은 운영 서버 HTTPS 전환 후 필요합니다.
- 허용되지 않은 네트워크에서 HTTPS 접근과 backend 직접 접속이 차단되는지 확인해야 합니다.
- CA 개인키의 오프라인 보관 전환과 서버 인증서 만료 점검·갱신 절차의 운영 정착이 필요합니다.
- 서버 랜카드에 남아 있는 보조 IP는 용도를 확인한 뒤 정리해야 합니다.
