# d-ddeck 1.0.3 — 구 서버(CS_Record) 정리 방식 반영

구 서버가 쓰던 **입력 규칙 · 재고 상태 규칙 · 통계 세는 법 · 매장 관리 방식**을 신 서버와 앱에 옮겼습니다. 자료 이관(1.0.2)에 이어 이번에는 "일하던 방식"이 그대로 옵니다. 상세 대응표: `docs/LEGACY_RULES.md`.

## 서버

- **대응 기록**: 브랜드→매장, 과실, 서비스구분·증상·제조사 최대 10쌍, 대응인원 여러 명, 렌탈(종류·시리얼·회수 예정일·회수 여부·실제 회수일)을 API 가 받습니다. 규칙 위반은 구 서버와 같은 문구로 거절합니다(서비스구분 1 필수, 증상은 그 구분의 것만, 로봇팔·제어박스·전동 그리퍼는 제조사 필수, 렌탈 시리얼은 재고 S/N 만, 종결에는 대응 내용·대응인원).
- **렌탈 ↔ 재고 연동**: 렌탈 저장 시 그 S/N 장비가 매장 '렌탈 중'으로, 회수 처리 시 '창고'로 돌아옵니다(이력에 기록 번호 남음).
- **재고 상태 규칙**: 설치·렌탈 중은 매장 필수, AS 대기·AS 반출은 매장에 둔 채 상태만, 창고·사무실·미상은 매장·세트 자동 비움. 같은 종류 안 S/N 중복 차단, 제조사 필수. 여러 대 한 번에 등록 · 한 번에 이동. 재고 현황(상태×종류 · 브랜드×종류 · 장소×종류 · 확인 목록 · 렌탈 중 D-day).
- **매장**: 폐점 처리 때 설치 장비를 회수 위치(바른 회수 · 창고 · 사무실 …)로 일괄 이동, 납품 세트 단위 장비 설정(없는 S/N 은 등록, 다른 곳 장비는 이동, 비전동 그리퍼 관리 번호 NG-0001 자동), 세트 이름·추가·삭제, 매장 상세에 서비스구분별 발생 · 미회수 렌탈 · 대응 이력.
- **통계**: 구 서버 표(연도×브랜드, 연도×매장, 브랜드×세부구분, 매장×세부구분, 제조사×연도, 연도별 운영 매장)를 크로스탭 API 로. 원인 수 기준 + 대응 건수 병기, 서비스구분 탭은 그 구분의 원인만. 연도 추이.
- **검색 조건 통일**: 목록 · 요약 · 통계 · 엑셀이 같은 조건(연도·월·브랜드·매장·구분·증상·제조사·과실·대응인원·상태·렌탈·검색어)을 씁니다.
- **엑셀 내려받기**: 대응 기록 · 재고(요약 + 종류별 시트) · 통계 표.
- **대시보드 API**: 미종결(오래된 순·경과일) · 렌탈 미회수 D-day · 최근 기록 · 연도별 건수.
- **캘린더 공휴일**: 한국 공휴일·대체공휴일 자동(2024~2050), 추가 휴일 설정.
- 새 저장소에도 회사 장비 종류 5종 · 상태 13종(규칙 포함) · 기본 품명·제조사 · 창고/사무실 위치가 기본으로 들어갑니다.
- SQLite 트랜잭션 처방: 규칙 위반으로 거절된 등록이 남지 않습니다.

## 앱 (Windows · Linux · Android 동시)

- 접수 화면이 구 서버 입력 양식과 같아졌습니다(브랜드→매장, 발생일, 발생 내용, 과실, 서비스구분 행 추가, 대응인원 칩, 렌탈 블록). 목록 필터 · 접수/종결/미종결 요약 · 엑셀.
- 상세에서 [종결 처리] 한 번(대응 내용·대응인원·대응일). 매장으로 바로 이동.
- 대시보드에 미종결 · 렌탈 미회수 · 최근 기록 · 연도별 건수.
- 재고 현황 탭 · 종류별 탭(위치 구분) · 체크박스 일괄 이동 · 상태 규칙에 맞는 이동 다이얼로그 · S/N 여러 개 등록.
- 매장 상세: 서비스구분별 발생 · 미회수 렌탈 · 대응 이력 · 폐점 처리(회수 위치 선택) · 장비 세트 설정 화면.
- 통계: 메인 + 서비스구분 탭, 구 서버 표 6종 + 운영 매장 표, 셀 클릭 → 목록, 엑셀.
- 캘린더에 공휴일 표시. 재고 보관 장소(위치) 관리 화면.
- 통계의 운영 매장 표는 CSV 로 내려받습니다(그 밖의 표는 엑셀).
