# d-ddeck 1.0.8 — 앱 내 업데이트와 Ubuntu 서비스 관리

Windows 프로그램과 Android 앱이 실행될 때 새 버전을 확인하고, 파일을 내려받아 설치 화면으로 연결합니다. 설정 메뉴에서도 업데이트를 확인할 수 있습니다.

- 다운로드 진행률·취소·재시도, 서명·SHA-256·파일 크기 검증을 지원합니다.
- Windows는 기존 설치 위치와 서버 주소를 유지합니다. Android는 출처 허용 설정 후 설치를 이어갑니다.
- 비공개 GitHub 인증은 서버에만 보관합니다. 서버가 검증한 릴리스 파일을 클라이언트에 제공합니다.
- Ubuntu 기존 폴더를 `ddeck.service`로 등록하는 도구와 구형 SQLite 보정·백업·검증 도구를 포함합니다.
- DB 검사 실패 시 systemd가 불필요하게 재시작을 반복하던 문제를 수정했습니다.

## 적용 순서

**1.0.7 이하에는 앱 내 업데이트 기능이 없으므로, 1.0.8을 최초 한 번 직접 설치해야 합니다.** 이후 버전부터 앱 내 업데이트를 사용할 수 있습니다.

1. Windows EXE 또는 Android APK로 기존 앱을 업데이트합니다. Android는 1.0.6·1.0.7과 동일한 운영 키로 서명합니다.
2. 서버 코드를 1.0.8로 반영하고 서비스를 재시작합니다. 1.0.7 대비 DB 마이그레이션은 없습니다.
3. 서버 파일 소유 계정으로 `bash deploy/sync_client_updates.sh v1.0.8`을 실행해 서명된 manifest와 설치 파일을 게시합니다. GitHub CLI 인증이 필요합니다.

`/home/...`에서 직접 운영 중인 서버는 `/opt/ddeck` 전용 설치·갱신 스크립트를 실행하지 마세요. 자세한 절차는 아래 문서를 따릅니다.

- [클라이언트 업데이트 운영 안내](https://github.com/kmeans12345-cell/d-ddeck_db/blob/v1.0.8/docs/CLIENT_UPDATES.md)
- [Ubuntu 서비스 등록 및 DB 보정](https://github.com/kmeans12345-cell/d-ddeck_db/blob/v1.0.8/deploy/README.md)

## 검증

Flutter 정적 분석, 앱 테스트 133개(기존 실서버 의존 19개 생략), 백엔드 스모크 254건, 업데이트 서명·파일 검증 및 다운로드 API, 배포 도구 테스트를 확인했습니다. Android 릴리스 빌드와 기존 배포 키 일치를 확인했습니다. Windows·Android 실기기에서 OS 설치 화면을 통한 최종 검수는 별도입니다.

설치 파일의 체크섬은 `SHA256SUMS`, 앱 내 업데이트용 서명 정보는 `update-manifest.json`으로 제공합니다.
