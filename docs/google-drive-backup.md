# Google 계정으로 공유 드라이브 자동 백업

이전 서버와 동일하게 **rclone에서 Google 계정으로 로그인**한 뒤 서버 PC가 Google Workspace 공유 드라이브에 업로드합니다. 서비스 계정 JSON 키는 필요하지 않습니다.

기존 `RCLONE_REMOTE` 기반 원격 백업은 제거되었습니다. 백업은 이 페이지에서 설정한 Google 드라이브에만 보관합니다. 기존 로컬 파일은 자동 삭제하지 않지만 새로운 로컬 보관본은 만들지 않습니다.

## 앱에서 최초 연결

1. **서버 PC 앱**에서 **관리 → 기능 설정 → Google 공유 드라이브 백업 → Google 계정으로 연결**을 누릅니다. 다른 PC나 Android에서는 백업 상태를 볼 수 있지만 Google 연결은 서버 PC에서 진행합니다.
2. 인증 방식을 선택합니다. 회사 OAuth 클라이언트가 있으면 ID와 보안 비밀번호를 입력합니다. 공용 설정으로 시도할 수도 있으나 rclone 공용 클라이언트는 2026년 중 종료 예정이므로 Google에서 거절하면 회사 OAuth 클라이언트가 필요합니다. [공식 설정 안내](https://rclone.org/drive/#making-your-own-client-id)
3. 서버 PC의 기본 브라우저가 열리면 백업에 사용할 Google 계정으로 로그인하고 권한을 허용합니다. 앱은 브라우저 인증이 끝날 때까지 기다립니다.
4. 앱에서 **공유 드라이브를 선택**합니다. 해당 계정에 업로드·휴지통 이동 권한이 있어야 합니다.
5. 폴더 목록에서 전용 백업 폴더를 선택합니다. 새 폴더를 원하면 경로를 입력하고 **폴더가 없으면 만들기**를 켭니다.
6. **이 폴더에 백업**을 눌러 적용합니다. **지금 백업**으로 실제 업로드를 확인한 뒤 **매일 자동 백업**을 켭니다.

서비스 계정 JSON 키나 터미널 명령 입력은 필요하지 않습니다. rclone은 서버에 설치되어 있어야 합니다. 현재 Ubuntu PC에는 설치되어 있습니다. 다른 서버는 [공식 설치 안내](https://rclone.org/install/)를 따르세요. 브라우저를 열 수 있는 데스크톱 세션에서 서버를 실행해야 합니다.

로그인은 최대 10분을 기다리며 취소·실패하면 기존 연결을 유지합니다. 폴더를 최종 저장하기 전까지 백업 계정을 변경하지 않습니다. 폴더 저장 시 접근을 확인하며 업로드·삭제 권한은 실제 백업에서 확인합니다. Google에서 권한을 거절하거나 공유 드라이브가 없으면 해당 Google 계정/조직 설정을 확인하세요.

## 자동 백업 및 최근 30개 보관

- 실행은 **서버 PC에서만** 진행합니다. 앱을 닫아도 서버가 켜져 있고 `SCHEDULER_ENABLED=true`이면 예약 시각(한국 시간, 기본 03:00)에 실행합니다.
- SQLite 온라인 백업 또는 PostgreSQL dump, 첨부파일, 체크섬 manifest를 ZIP으로 만들고 검증합니다. `.env` 및 Google 인증정보는 포함하지 않습니다.
- 업로드 후 rclone checksum 검증에 성공하면 해당 폴더의 `drive_YYYYMMDD_HHMMSS_ffffff.zip` 형식 파일을 최근 **30개**로 정리합니다. 오래된 것부터 하나씩 휴지통으로 이동합니다. 업로드·검증 실패 시 정리하지 않습니다.
- 현재 업로드한 백업은 보존합니다. 중복 파일명 등 목록 이상이 있으면 삭제를 중단하고 오류를 표시합니다. 정리에 실패한 경우에도 전체 성공으로 기록하지 않으며 다음 백업 때 다시 시도합니다.
- **이전 서버의 날짜별 백업 폴더, 일반 파일, 하위 폴더는 삭제하지 않습니다.** 30개 제한은 새 프로그램이 생성하는 백업 ZIP에 적용됩니다. 기존 자료까지 합산한 30개 제한은 아닙니다.
- 휴지통 파일은 즉시 영구 삭제하지 않으므로 저장 공간은 즉시 반환되지 않을 수 있습니다.
- 업로드용 임시 ZIP만 생성하며 업로드 작업이 끝나면 성공·실패 여부와 관계없이 삭제합니다. 로컬 보관과 별도 로컬 예약 작업은 사용하지 않습니다. 실패하면 Google 백업 페이지에서 다시 실행하세요.

## 계정 변경 및 해제

서버 PC 앱의 **연동 계정 변경**을 눌러 새 Google 계정으로 로그인한 후 공유 드라이브와 폴더를 다시 선택하세요. **이 폴더에 백업**으로 저장해야 이후 백업에 적용됩니다. 연결 중 실패하거나 취소하면 기존 설정은 유지됩니다. 기존 위치의 백업 파일은 이동하지 않습니다.

앱의 **연결 해제**는 자동 백업을 중지하고 앱의 대상 경로를 제거합니다. rclone 자체 로그인은 남습니다. 서버에서 인증까지 제거하려면 `rclone config`에서 해당 연결(앱 생성 연결 이름은 `ddeck_ui_…`)을 삭제하고 필요 시 Google 계정 보안 설정에서 접근을 해제하세요.

rclone 인증 파일은 서버 사용자 전용으로 보관하세요. 일반적으로 `~/.config/rclone/rclone.conf`이며 Git이나 백업 ZIP에 넣지 않습니다. 서비스 계정/OAuth의 기존 서버 설정 API는 호환 목적으로 유지하지만 새 화면은 rclone을 사용하며 최근 30개 정리는 rclone 연결에 적용됩니다.

## 백업 다운로드 · 서버 복구

서버 PC의 관리자 계정으로 Google 공유 드라이브 백업 페이지에서 **백업 다운로드 · 서버 복구**를 엽니다.

- **다운로드**: 백업 ZIP을 선택하고 저장 위치를 지정합니다. Google → 서버 다운로드와 체크섬 검증 후 선택한 PC 경로에 저장합니다.
- **서버 복구**: 목록에서 복구할 백업을 선택하고, 현재 DB·첨부파일 교체 안내를 확인한 뒤 **현재 서버 복구**를 누릅니다. 앱이 먼저 다운로드하고 ZIP 경로, manifest 체크섬, SQLite 무결성, 현재 DB와 같은 마이그레이션 버전인지 확인합니다.
- 검증 후 서버를 점검 상태로 전환하고 처리 중인 요청·예약 작업이 끝나기를 기다립니다. 현재 DB와 첨부파일의 안전 백업을 Google 드라이브에 업로드하고 검증한 뒤 교체합니다. 화면에 해당 Google 파일명을 표시합니다. 업로드에 실패하면 복구를 중단합니다. 안전 백업도 최근 30개 보관 대상입니다.
- 적용에 실패하면 원래 DB와 첨부파일로 되돌립니다. 원상복구까지 실패하거나 서버 전원이 꺼지면 점검 상태를 유지하므로 운영자가 안전 백업으로 복구해야 합니다. 점검 중 일반 API와 상태 확인(healthz)은 503을 반환합니다.
- 복구 후에는 **모든 사용자가 다시 로그인**해야 하며, 사용자 정보와 비밀번호도 백업 시점 기준입니다. 서버 `.env`, Google 연결 정보, 프로그램 버전은 교체하지 않습니다.
- 자동 복구는 **SQLite 서버, 동일 DB 마이그레이션 버전**만 지원합니다. PostgreSQL 백업은 다운로드 후 별도 운영 복구 절차를 사용합니다. 이전 서버의 날짜별 폴더는 이 목록에 포함하지 않습니다.
- 다운로드 임시 파일은 서버 사용자 전용 디렉터리에 저장합니다. 작업 조회 권한은 24시간 유효하며, 완료된 임시 파일은 24시간 경과 후 다음 목록 조회·다운로드 요청 때 정리합니다. 중단된 복구의 원상복구 자료는 점검 상태 동안 보존합니다.

### 복구 중 전원 장애 또는 원상복구 실패

1. 서버를 중지하고, 화면에 표시된 Google 안전 백업 파일명을 확인하고 공유 드라이브에서 다운로드합니다.
2. `deploy/backup_bundle.py --extract 백업.zip --destination 복구폴더`로 체크섬을 검증하고 추출합니다.
3. 기존 서버 복구 절차에 따라 DB와 첨부파일 저장소를 **함께** 복원합니다. SQLite의 기존 `-wal`/`-shm` 파일을 다른 DB 파일과 혼용하지 않도록 주의합니다. 환경설정과 Google 인증정보는 그대로 유지합니다.
4. DB·첨부파일 복원이 완료된 것을 확인한 뒤 `backups/.drive-private/restore-maintenance` 점검 표시 파일을 제거하고 서버를 시작합니다. 복원 전에 이 파일만 제거해 서비스를 재개하면 안 됩니다.

실제 운영 DB의 복구는 사용자가 최종 확인했을 때만 실행합니다. 개발 검증은 임시 SQLite DB와 첨부파일을 사용합니다.

## 업데이트·재시작 전 안전 백업

운영 스크립트의 수동 백업, 업데이트·재시작 전 데이터 백업도 같은 Google 계정을 사용합니다. Google 연결이 없거나 업로드 검증에 실패하면 업데이트·재시작을 중단합니다. 스크립트를 서버 계정과 다른 사용자로 실행할 때도 저장된 연결 설정을 사용합니다.

Linux 업데이트의 코드 되돌림 자료는 `update_…zip`으로 Google에 보관하며 별도로 최근 30개를 유지합니다. 서버에는 Google 파일 위치를 가리키는 작은 메타데이터만 남깁니다. 이 코드 ZIP에는 `.env`를 제외하며 되돌릴 때 현재 서버 환경설정을 유지합니다. 기존 버전의 로컬 되돌림 자료는 읽을 수 있습니다.

구형 `backup.sh --install-cron` / `backup-windows.ps1 -InstallTask`는 별도 로컬 예약을 해제하는 호환 명령입니다. 예약 시간은 앱의 Google 백업 페이지에서만 설정합니다. 사용자가 명시적으로 다운로드한 ZIP과 복구 중 필요한 임시 작업 파일은 자동 로컬 보관 백업과 구분합니다.
