# 사외 접속 (WireGuard VPN)

직원이 외근·재택 중에도 사내 DB 서버를 쓰게 하는 설정입니다.

**포트포워딩 없이, 서버를 인터넷에 노출하지 않고** 외부에서 접속할 수 있습니다.
WireGuard 포트 하나만 열려 있으면 되고, DB 서버(8000)는 계속 사내망에만 보입니다.

```
[직원 노트북] --암호화 터널--> [공유기 WireGuard] --> [DB 서버 192.168.121.2:443]
       |
       +--- 인터넷은 터널을 거치지 않고 평소 회선으로 직행 (분할 터널)
```

---

## 분할 터널 (Split tunnel)

핵심은 클라이언트 `.conf` 의 `AllowedIPs` 한 줄입니다.

```ini
# 전체 터널 - 인터넷까지 전부 회사 회선을 경유 (느려짐)
AllowedIPs = 0.0.0.0/0

# 분할 터널 - 회사 트래픽만 VPN, 인터넷은 직행  ← 권장
AllowedIPs = 192.168.121.0/24, 10.153.127.0/24
```

| | 전체 터널 | 분할 터널 |
|---|---|---|
| 인터넷 속도 | 회사 업로드 속도에 묶임 | 평소 속도 |
| 개인 웹서핑 | 회사 회선 경유 (로그 남음) | 직행 |
| 항상 켜두기 | 부담됨 | **부담 없음** |

분할 터널이면 VPN 이 연결돼 있어도 **회사 서버로 갈 때만** 터널을 씁니다.
그래서 "프로그램 실행할 때만 켠다" 같은 장치 없이, **부팅 시 자동 연결로 두면 됩니다.**

### 권장 클라이언트 설정

```ini
[Interface]
PrivateKey = <기기마다 다름>
Address    = 10.153.127.X/24
# DNS 는 분할 터널에서 불필요 (IP 로 접속하므로)

[Peer]
PublicKey    = <서버 공개키>
PresharedKey = <기기마다 다름>
AllowedIPs   = 192.168.121.0/24, 10.153.127.0/24
Endpoint     = <공인IP>:<포트>
PersistentKeepalive = 25
```

`PersistentKeepalive = 25` 는 공유기 NAT 매핑이 끊겨 첫 접속이 지연되는 것을 막습니다.
넣어두는 편이 체감이 좋습니다.

## 직원 PC 등록 (기기마다 반복)

### 1단계 — 공유기에서 피어 발급 (관리자)

`http://192.168.121.1` → 관리도구 → 고급 설정 → 특수기능 → VPN 설정 → WireGuard

**기기마다 피어를 따로** 만듭니다. 한 설정을 여러 명이 돌려쓰면 한 대를 분실했을 때
전원 재발급해야 합니다.

- 이름: "홍길동 노트북" 처럼 누구 것인지 알아보게
- 발급하면 `.conf` 파일과 **QR 코드**가 나옵니다

### 2단계 — 설정 파일 손보기 (관리자, PC 에서)

공유기가 만든 `.conf` 는 보통 `AllowedIPs = 0.0.0.0/0` 이라 직원 인터넷까지
회사 회선을 타게 됩니다. 발급받은 파일들을 한 폴더에 모아두고:

```powershell
.\deploy\fix-wireguard-conf.ps1 -Path .\peers -Endpoint ddeck.iptime.org
```

분할 터널 적용, DNS 주석 처리, `PersistentKeepalive` 추가, Endpoint 를 DDNS 로
교체까지 한 번에 합니다. 원본은 `.conf.bak` 으로 백업되고 비밀키는 손대지 않습니다.

`-Endpoint` 는 DDNS 를 설정했을 때만 쓰세요. 공인 IP 를 그대로 두면 IP 가 바뀔 때
전원 재배포해야 합니다.

### 3단계 — 직원 PC 에 설치

1. [wireguard.com/install](https://www.wireguard.com/install/) 에서 WireGuard 설치
   (관리자 권한 필요. 설치는 한 번만)
2. WireGuard 실행 → **"터널 추가" → "파일에서 터널 추가"** → 해당 `.conf` 선택
3. **활성화** 버튼 클릭
4. 재부팅 후에도 자동 연결되는지 확인 — 안 되면 터널 목록에서 해당 터널의
   자동 시작 옵션을 켭니다

> 휴대폰(안드로이드)은 Play 스토어에서 WireGuard 앱 설치 후 **QR 코드 스캔**이
> 가장 빠릅니다. 다만 QR 은 공유기가 만든 원본(전체 터널)이라, 분할 터널을
> 원하면 앱에서 AllowedIPs 를 직접 수정해야 합니다.

### 4단계 — 확인

직원 PC 에서 (VPN 활성화 상태로):

```powershell
ping 192.168.121.2
curl --cacert app/assets/company_ca.crt https://192.168.121.2/healthz     # {"status":"ok"} 가 나와야 정상
```

그다음 d-ddeck 앱을 실행해 로그인되면 끝입니다.
앱의 서버 주소는 **사내망과 동일하게 `https://192.168.121.2`** 입니다.

### 5단계 — 서버 쪽 방화벽 (최초 1 회만)

DB 서버 PC 에서 관리자 PowerShell:

```powershell
Set-NetFirewallRule -DisplayName "d-ddeck DB Server" `
  -Profile Any -RemoteAddress LocalSubnet,10.153.127.0/24
```

## 자주 걸리는 문제

### VPN 은 연결됐는데 앱만 접속이 안 됨

**사설 대역 충돌**입니다. 집이나 외부 공유기가 회사와 같은 `192.168.0.x` 를 쓰면,
`192.168.121.2` 을 찾을 때 VPN 이 아니라 **그 집의 192.168.121.2** 으로 갑니다.
국내 공유기 상당수가 `192.168.121.1` 을 기본값으로 쓰므로 실제로 자주 발생합니다.

확인:
```powershell
Get-NetRoute -DestinationPrefix '192.168.121.0/24' | Select-Object InterfaceAlias, NextHop
```
`InterfaceAlias` 가 WireGuard 어댑터가 아니면 충돌입니다.

해결 (위쪽이 확실함):
- **회사 공유기 대역을 흔치 않은 값으로 변경** — 예: `192.168.37.0/24`
  (사내 전체 재설정이 필요하지만 한 번 하면 끝납니다. DB 서버 IP 와 클라이언트
  설정 주소도 함께 바꿔야 합니다)
- 그 PC 만 임시로 집 공유기 대역 변경

### 연결은 되는데 느리거나 끊김

- `PersistentKeepalive = 25` 가 있는지 확인
- MTU 문제라면 `[Interface]` 에 `MTU = 1380` 추가

### 사무실에서도 VPN 이 켜져 있어도 되나

됩니다. 분할 터널이면 같은 네트워크 안에서는 라우팅이 로컬로 잡혀
VPN 을 거치지 않습니다. 끄고 켜는 수고를 하지 않아도 됩니다.

## 보안

**`.conf` 파일은 비밀번호와 같습니다.** `PrivateKey` 와 `PresharedKey` 가 들어 있어
유출되면 누구나 사내망에 들어올 수 있습니다.

- 카카오톡·이메일로 보내지 마세요 (서버에 사본이 남습니다). QR 코드나 USB 로 전달
- **기기마다 별도 피어** — 분실 시 그 피어만 삭제하면 됩니다
- **Git 에 커밋 금지** — 이 리포지토리의 `.gitignore` 에 `*.conf` 를 넣어두었습니다
- 퇴사자 발생 시 해당 피어 즉시 삭제

**DB 서버 포트(8000)는 절대 포트포워딩하지 마세요.** VPN 을 쓰는 이유가 그것입니다.
현재 서버는 HTTP 평문이라 인터넷에 직접 노출하면 로그인 비밀번호와 인증 토큰이
그대로 흐릅니다. 열려 있어야 할 것은 WireGuard 포트 하나뿐입니다.

## 참고: "프로그램 실행 시에만 VPN 켜기"

기술적으로 가능하지만 권하지 않습니다.

- WireGuard 터널의 시작/중지는 관리자 권한이 필요해서, **PC 마다 최초 1 회**
  서비스 권한을 따로 부여해야 합니다
- 분할 터널이면 항상 켜두어도 인터넷에 영향이 없어, 얻는 이득이 거의 없습니다

그래도 필요하시면 (예: 개인 노트북이라 터널을 상시 띄우고 싶지 않은 경우)
런처 방식으로 만들 수 있습니다 — 사내망이면 VPN 없이 실행, 외부면 자동 연결 후
앱 종료 시 해제.

## Windows 앱에서 등록·연결·해제

새 Windows 클라이언트는 로그인 화면과 **사외 접속(VPN) 설정**에서 `.conf` 등록, 연결 스위치, 등록 해제를 제공합니다. 공식 [WireGuard for Windows](https://www.wireguard.com/install/)를 먼저 설치하세요. 앱의 **WireGuard 설치 안내** 버튼으로 설치 페이지를 열 수 있습니다.

- `.conf`를 등록하면 OS 보안 저장소에 보관합니다. 전체 터널은 기존 Android와 동일하게 사내망용 분할 터널로 변환합니다.
- 연결은 공식 WireGuard 터널 서비스를 생성합니다. Windows 관리자 권한 요청(UAC)을 승인해야 하며, 취소하면 등록된 설정은 유지합니다.
- Windows 사용자별 전용 터널 이름(`ddeck_…`)을 사용하므로 다른 WireGuard 터널을 제어하지 않습니다.
- 서비스 실행에 필요한 `.conf`는 `%LOCALAPPDATA%\D.DDECK\vpn`에 두며 사용자·SYSTEM·관리자만 읽을 수 있게 접근권한을 제한합니다. 해제하면 서비스와 해당 실행용 설정 파일을 제거하고, 등록 해제하면 OS 보안 저장소의 설정도 제거합니다.
- 앱을 종료해도 VPN 연결은 유지됩니다. 해제하려면 앱에서 스위치를 끄세요. 표시되는 연결 상태는 Windows 터널 서비스 상태이며 서버 통신 성공까지 보장하지 않습니다.
- 관리자 명령 실행 훅(PreUp/PostUp/PreDown/PostDown)이 들어간 설정은 지원하지 않습니다. 키와 예외 원문은 화면이나 로그에 표시하지 않습니다.
- Linux 앱의 내장 터널 제어는 지원하지 않으며 Android의 기존 VPN 연결 방식은 유지합니다.

구현 검증: 상태 전환·권한 취소·등록 보존 테스트와 PowerShell 구문 검사를 수행합니다. 실제 Windows UAC 승인과 드라이버 연결은 Windows PC에서 별도로 확인해야 합니다.
